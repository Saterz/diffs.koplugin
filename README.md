# diffs.koplugin

A KOReader plugin for viewing the changes between two revisions of a GitHub repository.

> [!WARNING]
> This plugin was fully generated by artificial intelligence. Human review, testing, and project direction remain important, but the source code was produced by AI.

## Installation

### Recommended: ZenPM

ZenPM is a package manager for KOReader plugins. It is the recommended way to install Diffs because adding the custom repository ensures you receive new versions as soon as they are released.

1. Install [ZenPM](https://github.com/xZenLabs/zen-pm) if you have not already.
2. Open ZenPM's **Sources** screen and add `https://zenpm-repo.saterz.dev`.
3. Refresh the sources, then find and install **Diffs**.

### Other options

- Install **Diffs** from a third-party KOReader plugin app store.
- Download the latest release from the [GitHub Releases page](https://github.com/Saterz/diffs.koplugin/releases) and install it manually.

## Usage

Open **Tools → Diffs → Compare**, and enter:

1. A repository owner such as `koreader`.
2. A repository name such as `koreader`.
3. A base commit, branch, or tag.
4. A head commit, branch, or tag.

To configure authentication, open **Tools → Diffs → Settings → GitHub API key** and enter an optional GitHub API key. The key is sent as a Bearer token with both GitHub requests. It can raise GitHub's API rate limit and allow access to repositories that key may read. The key is stored in KOReader's local `Diffs/github_api.key` file, so clear it before sharing the device or its settings backup.

Without a token, the plugin uses GitHub's unauthenticated API and supports public repositories only. GitHub may temporarily reject requests after its anonymous rate limit is reached.

### Comparing plugins from ZenPM

With both Diffs and ZenPM enabled, restart KOReader and open an installed plugin's action menu in ZenPM. For packages whose `source` points to a GitHub repository, **View changes** opens the Diffs comparison form with that repository and the installed/latest versions prefilled. When ZenPM would normally update directly, Diffs first offers **Update** and **View changes**, so Advanced mode is not required. Change either revision to compare any two versions, then tap **Compare**. Viewing changes does not install, update, or queue the plugin.

Missing or unknown revisions are left blank. ZenPM version labels are not always Git tags: if needed, enter the exact tag (including a `v` prefix), branch, or commit used by the repository. The comparison shows repository changes, not differences between downloaded release archives.

The integration is optional and requires ZenPM's `zenpm_app` lazy loader and `ui/modals.package_modify` menu API. No ZenPM files are modified; packages without a supported GitHub source keep their existing menus. GitHub authentication and rate limits are the same as for comparisons opened from Tools.

## Releases

Releases are created automatically by GitHub Actions when a version tag is pushed. Tags use the form `vMAJOR.MINOR.PATCH`, optionally followed by a prerelease suffix such as `-beta.1` or `-rc.1`.

The workflow checks the codebase, packages the Lua files, and attaches `diffs.koplugin.zip` to the GitHub Release. Beta tags must point to a commit reachable from the `dev` branch.

Release notes come from `CHANGELOG.md`, which follows the [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) format. Stable tags use their matching version section, while beta and other prerelease tags use the `Unreleased` section. Add ongoing changes under `Unreleased` and organize them under the appropriate categories, such as `Added`, `Changed`, `Fixed`, or `Security`.

## Known limitations

- Git combined-merge diffs are not supported.
- Git binary patch payloads are identified but not decoded.
- Syntax highlighting and user-configurable themes are not currently supported.
